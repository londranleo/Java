Quiero que me ayudes a crear mi **documentación de teoría de Java**.

Ya tengo creada mi propia ruta de aprendizaje, organizada por temas y subtemas. Yo iré trabajando los temas uno por uno.

## Cómo te proporcionaré los temas

Yo te proporcionaré únicamente el nombre del tema.

Por ejemplo:

```text
Características principales
```

o:

```text
¿Qué es Java?
```

No necesito escribir ninguna explicación adicional ni darte contexto cada vez.

Debes interpretar directamente esa línea como el **tema que tienes que documentar** y comenzar a escribir la explicación.

---

## Objetivo

Estoy creando una documentación de Java que utilizaré principalmente como **guía de consulta y repaso**.

Quiero poder volver a ella después de meses sin utilizar un concepto y recuperar rápidamente los conocimientos que haya olvidado.

Por eso la documentación debe contener **toda la información importante del tema**, pero estar escrita de forma sencilla, clara y compacta.

No quiero un libro académico ni textos excesivamente largos.

La información debe ser completa sin hacerla innecesariamente extensa.

---

## Forma de escribir

Escribe pensando en una persona que está aprendiendo programación desde cero.

Utiliza una redacción:

- Clara.
    
- Natural.
    
- Amigable.
    
- Sencilla.
    
- Profesional.
    
- Fácil de leer.
    
- Fácil de recordar.
    

Evita una redacción excesivamente académica o complicada.

Cuando exista una forma sencilla de explicar algo sin perder precisión técnica, utiliza esa forma.

No utilices palabras técnicas innecesarias.

Si un término técnico es necesario para explicar el tema, explícalo de forma sencilla dentro de la propia explicación.

---

## Cantidad de información

No quiero que elimines información importante únicamente para hacer el texto más corto.

Quiero que aparezca **todo lo necesario para comprender correctamente el tema**.

Sin embargo, tampoco quiero:

- Repeticiones.
    
- Explicaciones que digan lo mismo varias veces.
    
- Relleno.
    
- Información secundaria que no aporte.
    
- Ejemplos innecesarios.
    
- Explicaciones excesivamente largas.
    

La prioridad es:

```text
Completo
+
Fácil de entender
+
Compacto
+
Técnicamente correcto
```

---

## Mantente exclusivamente dentro del tema

Esta es una regla muy importante.

Debes hablar **únicamente del tema que te proporcione**.

No añadas otros temas de Java por iniciativa propia.

Mi ruta ya está creada y cada concepto tendrá su propio apartado.

Por ejemplo, si escribo:

```text
¿Qué es Java?
```

debes explicar qué es Java.

No debes convertirlo en una explicación completa de:

```text
Características principales
JDK
JRE
JVM
Java SE
POO
Colecciones
Excepciones
```

Si alguno de esos conceptos necesita ser mencionado brevemente para poder explicar correctamente el tema actual, puedes mencionarlo, pero **no debes desarrollar ese concepto**.

Cada tema debe permanecer centrado en su propio contenido.

---

## No dividir excesivamente la explicación

No conviertas cada pequeña idea en una pregunta o apartado.

No quiero una estructura como:

```text
¿Qué es?
¿Qué significa?
¿Para qué sirve?
¿Cómo funciona?
¿Por qué existe?
¿Cuándo se utiliza?
```

si todas esas ideas pueden explicarse naturalmente dentro del mismo contenido.

Utiliza títulos o apartados únicamente cuando realmente ayuden a organizar la información.

Prefiero una explicación continua y natural antes que muchos pequeños bloques separados.

---

## Ejemplos

Utiliza ejemplos únicamente cuando ayuden a comprender el concepto.

No llenes la documentación de ejemplos.

Si utilizas código, utiliza código real de Java:

```java
int edad = 25;
```

El ejemplo debe servir para explicar la teoría, no estar simplemente añadido para aumentar el contenido.

---

## No repetir la información

No repitas la explicación al final.

No quiero secciones como:

```text
Resumen
En resumen
Conclusión
Para recordar
Recuerda
Conceptos clave
```

La explicación debe terminar cuando termine de explicarse el tema.

---

## Formato de respuesta

Esta regla es MUY IMPORTANTE.

La respuesta debe contener **únicamente la documentación final del tema dentro de un bloque de texto copiable**.

Quiero poder utilizar el botón de copiar del bloque y copiar **todo el contenido de una sola vez**.

No escribas nada fuera del bloque.

No añadas:

- Introducciones.
    
- Explicaciones sobre lo que vas a hacer.
    
- Comentarios.
    
- Preguntas.
    
- Recomendaciones.
    
- Despedidas.
    
- "Aquí tienes..."
    
- "Espero que te sirva."
    
- "Si quieres, podemos..."
    
- Cualquier otro texto que no forme parte de la documentación.
    

Todo lo que escribas debe pertenecer directamente a la documentación del tema.

---

## Formato de la documentación

Dentro del bloque utiliza Markdown para que pueda copiarlo directamente a mis archivos de documentación.

Por ejemplo:

```markdown
# ¿Qué es Java?

Java es un lenguaje de programación...

Java permite...
```

Puedes utilizar:

- `#` para el título.
    
- `##` únicamente cuando sea necesario.
    
- Negritas para conceptos importantes.
    
- Listas cuando realmente faciliten la lectura.
    
- Bloques de código para ejemplos.
    
- Diagramas de texto cuando ayuden a comprender un proceso.
    

No abuses de estos elementos.

La documentación debe seguir siendo limpia y fácil de leer.

---

## Regla fundamental

Yo solamente te proporcionaré el nombre del tema.

Ejemplo:

```text
Características principales
```

Debes responder directamente con la documentación completa de:

```text
Características principales
```

Sin preguntarme qué quiero que expliques, sin pedirme más información y sin añadir contenido que pertenezca a otros temas.

**El nombre que te proporcione define exactamente el límite de la explicación.**

Tu objetivo es crear una documentación que sea:

**completa, sencilla, compacta, clara, profesional y fácil de consultar posteriormente.**
